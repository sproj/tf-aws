# cluster/

One Terraform root, applied after `cluster_ingress/`, that installs the
in-cluster workload plumbing and the shared datastores on top of it. It's
split into four nested modules so each concern has its own file set, but
they share one state file (`examples/kubernetes-ec2/layered/cluster/terraform.tfstate`).

```
cluster_workload/       EBS CSI driver + storage class, AWS LBC (both via Helm),
                        ClusterSecretStore, block-imds NetworkPolicy, and the
                        cert-manager ClusterIssuer + its ExternalSecret. Applied
                        first — everything else depends on the CSI storage
                        class and the ClusterSecretStore it creates.

cluster_databases/      `databases` namespace: a StatefulSet Postgres instance,
                        per-application ExternalSecrets-backed credentials
                        (analytics, url_shortener) applied via a Job that runs
                        `CREATE USER`/`CREATE DATABASE`, and a standalone Redis
                        Deployment in its own `redis` namespace.

cluster_messaging/       `rabbitmq` namespace: a single RabbitMQ Deployment,
                        config, and ExternalSecret for the credentials
                        generated by ../../../../bootstrap/rabbit-mq-credentials/.

cluster_observability/   `observability` namespace: a shared Jaeger instance
                        (Deployment + Service) that applications send traces to
                        at http://jaeger.observability.svc.cluster.local:4317.
```

`cluster_databases`, `cluster_messaging`, and `cluster_observability` all set
`depends_on = [module.cluster_workload]` — they need the ClusterSecretStore
CRD instance it creates to resolve their `ExternalSecret`s.

## Prerequisites

This layer assumes `cluster_operators/` (ESO + cert-manager CRDs, kube-prometheus-stack)
and `cluster_ingress/` (ingress-nginx) have already been applied — the
`ExternalSecret`/`ClusterIssuer` manifests here reference CRDs those layers
install, and will fail to apply otherwise. See the full apply order in
[`../../../../notes.md`](../../../../notes.md).

## Adding a new application database

Follow the pattern in `cluster_databases/url_shortener_postgres_credentials.tf`:
a `random_password`, three `aws_ssm_parameter`s, a `kubernetes_config_map_v1`
mounting the actual `CREATE USER`/`CREATE DATABASE` statements from a `.sql`
file under `sql/` (per the root `CLAUDE.md` Kubernetes rule — the SQL itself
must live in a file, not inline), and a `kubernetes_job` whose `args` is just
a thin wait-for-postgres-then-`psql -f` wrapper around that mounted file.
